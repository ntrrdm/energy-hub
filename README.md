# EnergyHub — прозрачность энергохаба в один клик

Интерактивный frontend-прототип на React 19, TypeScript и Vite. Он объединяет площадки, почасовые профили, Grid/PV, оборудование, качество данных, услуги, локальные настройки и журнал событий в одном рабочем пространстве. Главный принцип — один и тот же набор данных показывается с детализацией, нужной выбранной роли. Состав команды в предоставленных материалах не указан.

## Состав проекта

- `src/` — React-интерфейс, доменная логика и тёмная тема (`#102537`, бирюзовый акцент `#15a69a`).
- `data/raw/` — шесть демонстрационных CSV; `data/case6-aggregated.json` — агрегаты, используемые приложением.
- `scripts/build-case6-data.js` — воспроизводимая обработка CSV.
- `tests/domain.test.ts` — проверки расчётов и матрицы разрешений.
- `energyhub-legacy.html` — исходный автономный макет для сравнения.
- `data-model.md`, `DEMO_SCRIPT.md` — логическая модель и сценарий защиты.
- `FINAL_REPORT.md` — заметки о проверке и выявленных ограничениях.

## Требования и запуск локально

Нужны Node.js 22 или новее и npm. Для чистого запуска:

```bash
npm ci
npm run data
npm test
npm run build
npm run dev
```

Откройте URL, напечатанный Vite (обычно `http://localhost:5173/`). Также доступен вход `/energyhub.html`. Production-проверка: `npm run preview` после успешной сборки.

## Запуск Docker

Docker Desktop с Compose:

```bash
docker compose up --build
```

Затем откройте `http://localhost:8080/`. Контейнер собирает агрегаты и Vite bundle, затем отдаёт статический сайт через Nginx. Остановка: `docker compose down`.

## Роли и разрешения

Переключатель в шапке демонстрационный; регистрации и реальной аутентификации нет.

| Роль | Область и стартовый фокус | Доступные действия в прототипе |
|---|---|---|
| Администратор платформы | Все площадки, каталог и подключённые услуги | Добавление объектов, оборудование, подключение/отключение услуг, тарифы и календарь |
| Владелец портфеля | Сводка и сравнение доступных площадок | Просмотр агрегатов, переход к площадке и её сервисам; настройки только для чтения |
| Оператор хаба | Детали выбранного хаба, лимиты, данные и обслуживание | Изменение лимита объекта и оборудования; создание и изменение статуса заявки обслуживания |
| Собственник здания | Площадка «Север» и её объектные показатели | Просмотр своих площадок, услуг, качества и истории; режим чтения |

Разрешения реализованы только клиентскими условиями React. Они не являются границей безопасности: в промышленной системе проверки должны выполняться сервером.

## Пользовательские сценарии

1. Администратор подключает услугу в разделе «Сервисы», выбирая услугу, область и цель; шаблон перечисляет нужные виджеты и данные.
2. Владелец портфеля смотрит площадки и открывает обзор выбранного объекта.
3. Оператор переходит от объекта к его показателям, проверяет источник и качество, меняет допустимый лимит.
4. Оператор заводит заявку обслуживания и проводит её по состояниям «Открыта → В работе → Закрыта».
5. Пользователь формирует представление одним из поддерживаемых локальных запросов; рядом показаны использованные данные.
6. Собственник здания просматривает контур площадки «Север» в режиме чтения.

Полный поминутный план демонстрации находится в [`DEMO_SCRIPT.md`](DEMO_SCRIPT.md).

## Модель данных

Приложение работает с клиентскими объектами `Portfolio/site`, `EnergyObject`, `Asset`, `Connection`, `TariffBand`, `Schedule`, `ServiceLink`, `MaintenanceItem` и `EventItem`. Ключи связывают объект с площадкой, подключение услуги — с целью, заявку — с объектом, а оборудование — с площадкой и рёбрами топологии. Значение `null` в измерении означает пропуск, не нулевое потребление. Подробные сущности, кратности и правила описаны в [`data-model.md`](data-model.md).

## Данные и правила формирования представлений

Скрипт читает CSV с `;`, берёт последние 96 интервалов (24 часа при шаге 15 минут) и объединяет каждые четыре интервала в час. Demand, Grid и PV остаются раздельными рядами; неполный агрегат сохраняет `null`. Для графика объекта используются измерения Demand, для сценария Peak shaving — Grid, доступная мощность батарей, целевой/календарный лимит и цена покупки. Текущая экономическая оценка — упрощённая симуляция.

В каталоге перечислены шаблоны Peak shaving, мониторинга профиля и EV-нагрузки. Подключение хранит идентификатор услуги, уровень, цель, статус и лимит; открытие подключения ведёт в соответствующий обзор/панель объекта. **Автоматическая адаптация каталожных шаблонов к произвольным каналам и оборудованию пока частичная:** описания виджетов сохранены как правила-прототипы; полноценного универсального движка шаблонов и проверки необходимых входов нет. Создание объекта добавляет его в объектный реестр и агрегаты; автоматической сборки новых узлов топологии из CSV нет.

## Запросы для визуализации

Запросы разбираются локальными правилами, без внешней модели. Поддержаны три группы:

- «Сравни потребление площадок» — суммы известных значений Demand за последние 24 часа.
- «Покажи объекты с пропусками данных» — объекты с `null` в ряду или флагом качества `gap/suspect`.
- «Покажи лимиты и пики» — текущий лимит площадки и переход к данным/сценарию Peak shaving.

Неподдерживаемый текст получает подсказку с примерами. Интерфейс сообщает об источниках и сохраняет семантику пропусков. Это шаблонный локальный разбор, а не ИИ и не произвольный конструктор графиков.

## Услуги, лимиты и обслуживание

Каталог включает Peak shaving, мониторинг энергопрофиля и управление зарядной нагрузкой. Допустимые области указаны в карточках услуг: площадка, оборудование и/или энергохаб. Сейчас подключение демонстрационное и хранится в `localStorage`; участие конкретного оборудования и проверка требований к данным не валидируются полностью. Лимит управляет локальным сценарием и не передаётся устройству. Журнал событий и заявки также локальны для браузера.

## Сброс и сохранение

Роль, выбранная площадка, конфигурация, услуги, заявки и история хранятся в `localStorage` этого браузера. Кнопка с круговой стрелкой удаляет демо-состояние и возвращает стартовые наборы. CSV-данные исходников при этом не меняются.

## Переменные окружения и внешние зависимости

Секреты не нужны; пример находится в [`.env.example`](.env.example). Карта загружает публичный стиль/тайлы OpenFreeMap, а источник и условия его использования следует проверить перед показом во внешней сети. Остальные демонстрационные сценарии работают без обязательных платных сервисов. Графики — Apache ECharts, топология — React Flow, карта — MapLibre GL JS.

## Ограничения

- Нет backend, БД, API, аутентификации, серверной авторизации и общей синхронизации между браузерами.
- Нет реальных BMS/SCADA/EMS-интеграций и команд оборудованию.
- Нет полного конструктора дашбордов, универсальной системы сервисных шаблонов, правил маршрутизации сервисов и валидации объектов/каналов.
- Реестр обслуживания и журнал не являются полноценной CMMS и не имеют назначений исполнителей/дедлайнов.
- Ряд демонстрационных показателей и координат синтетический; CSV-архив используется в профилях, но не является промышленной телеметрией.
- Peak shaving не учитывает round-trip КПД, деградацию, температурные и договорные ограничения, резерв мощности и проверенную тарификацию. Результат не подходит для реальных финансовых или диспетчерских решений.
- Публичные тайлы требуют сети; без сети карта может быть недоступна, остальные экраны остаются локальными.
