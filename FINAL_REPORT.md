# Отчёт о проверке EnergyHub

## Изменения в этой поставке

- Добавлены раздел «Сервисы» с тремя демонстрационными услугами, параметрами подключения и кнопкой перехода к представлению.
- Добавлена форма локальной визуализации с тремя группами запросов: сравнение Demand, качество данных, лимиты/пики. Ответ сообщает использованный ряд и обращение с пропусками.
- Добавлен список заявок обслуживания со статусами «Открыта → В работе → Закрыта»; создание и смена статуса ограничены ролью оператора.
- Исправлена матрица разрешений: владелец портфеля — просмотр, добавление объекта доступно администратору; собственник здания ограничен площадкой «Север».
- Переписаны README и модель данных с описанием реальных возможностей и оставшихся ограничений. Подготовлена шестислайдовая презентация в палитре проекта.

## Проверено

- Доменные тесты Node.js: **8/8 прошли** командой `node --experimental-strip-types --test tests/domain.test.ts`.
- `scripts/build-case6-data.js`: успешно обработал 6 CSV и пересоздал агрегат.
- PowerPoint: PPTX содержит 6 слайдов; структурная проверка пакета прошла без ошибок, геометрическая проверка — 0 замечаний. Все слайды экспортированы в превью и осмотрены.

## Не удалось проверить

- `npm run build` не прошёл в этой среде. Архив не содержал `node_modules`, системный npm недоступен, а попытка установить зависимости через доступный pnpm завершилась ошибкой Windows `EPERM` при создании symlink. Поэтому production-сборка и TypeScript typecheck остаются **непроверенными**.
- Интерактивный браузерный проход по новым страницам не запускался: зависимости React/Vite отсутствуют. Доменные тесты не проверяют React UI.
- Docker build не запускался; он потребует Docker Engine и загрузки базовых образов.

## Оставшиеся предметные ограничения

- Каталог/подключения и шаблоны демонстрационные; правила обязательных каналов/оборудования и адаптация дашборда к произвольной конфигурации неполны.
- Запросы — локальные строки и условия, а не ИИ и не свободный конструктор графиков.
- Авторизация, backend, БД, общая синхронизация, реальные интеграции и диспетчеризация команд отсутствуют.
- Услуги и заявки сохраняются в `localStorage`; нет исполнителей, сроков и полноценного журнала обслуживания.
- Координаты примерные, карта зависит от публичных тайлов; расчёт Peak shaving — упрощённая симуляция.
